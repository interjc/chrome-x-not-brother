# Usage workflow

1. Build and load `dist/` as an unpacked Chrome extension.
2. Use the automatically opened install guide or side panel to review the prominent local-data disclosure and affirmatively consent before observation begins. Before consent, the expanded X dock, the entry beside its collapsed NB button, and the action-icon context menu may reopen that disclosure; none of those entry points records consent by itself.
3. Browse `https://x.com` normally. Do not expect the extension to auto-scroll or open profiles.
4. Read the compact badge beside recognized users. Insufficient evidence produces no badge or local record.
5. Read the toolbar badge: lime `ON` is active; gray `!` is paused; amber `!` needs first-run setup.
6. Use the X-page observer dock for local counts and click it to open the side panel. After consent, the expanded dock also shows whether custom blacklist rules are applying and how many rules exist, with an Edit rules action that opens the fieldbook blacklist page. Its `×` minimizes it to a status-bearing NB floating button that stays in the bottom-right corner; while that button is shown, shift X's Chat/Grok drawers up so they do not cover the ball or the timeline. Activate the button to restore the overview and drop the shift. While consent is missing, keep a separate high-contrast native button beside the bubble that opens the disclosure, and do not show the blacklist row. The presentation preference persists locally.
7. Open the fieldbook for full search, filtering, sorting, change review, export, import, local deletion, or full local reset. Use the Archive, Blacklist, and Settings tabs as separate pages.
8. Use the Side Panel or Fieldbook footer feedback link to open `https://github.com/interjc/chrome-x-not-brother/issues`. Do not attach passwords, cookies, or real relationship exports.

Optional timeline filters stay off until enabled in the Side Panel Options tab (toolbar icon right-click → Options) or the fieldbook. “Hide muted accounts completely” hides Home, search, notification, and thread posts from muted authors even when the follow is mutual. “Hide accounts that blocked you” hides posts from locally known blocked-by handles on those same surfaces. Accounts already in the local list hide immediately; a newly detected author collapses with a short animation. Profile pages, hover cards, and follow lists stay visible. Filters never click mute/block controls or store a mute list.

“Apply custom blacklist rules” is the third default-off filter. An always-available “Edit rules & view guide” action sits beside it and deep-links to the fieldbook editor; in the fieldbook it reveals and focuses the editor in place. The built-in localized guide covers each target, safe regex authoring, expiration, OR behavior, update-by-id or replace import, privacy, and a complete JSON example. After consent, the HoverCard name cluster, the tweet more menu, and a tweet-text selection can each save one rule immediately without opening the editor. The editor supports exact normalized X handles, display-name contains/safe-regex, content contains/safe-regex, per-rule enablement, and expiration. Rules stay in local storage namespaced by the signed-in X handle; only the master switch syncs. File import, one-time public HTTPS/Gist import with Chrome's per-source permission prompt, independent JSON export (with rule ids), update-by-id or replace import, and clear are available. Point install users at the root `README.md` section on custom blacklist rules for UI authoring, export/import, and recommended public hosting (Gist, GitHub Raw, other anonymous HTTPS). Use `skills/x-not-brother-rules` when authoring an exported JSON file with an AI. Post text is matched transiently and never stored. Use [filter-rules.md](filter-rules.md) for protocol work.

The side panel, fieldbook, and toolbar copy default to the Chrome UI language. The side panel and fieldbook language switcher can override that with English, Japanese, or Simplified Chinese; the choice is stored as a small Chrome Sync preference named `uiLocale` and defaults to follow-the-browser. A manual choice also updates relationship badges and the observer dock on x.com; `auto` keeps those surfaces on the X page language. Unsupported locales fall back to English. If Chrome is signed out or sync is disabled, the same setting remains local to that browser. The relationship archive and signed-in X handle never sync.

“Blocked you” is opportunistic: it is collected from a directional platform notice, when reply/repost/like are real controls that are explicitly disabled with a normal same-layer baseline, or from a fully loaded already-visible hover card that has no relationship-count links. Generic unavailable-post text, a single disabled repost, empty engagement shells, and photo-lightbox scroll locks are not evidence. Once known locally, the relation can annotate later cards for the same handle. The extension cannot enumerate every account that has blocked the viewer. The signed-in viewer and unknown results are excluded from all observation UI.

Home timeline cards usually omit follow controls, but X already loads `following` / `followed_by` into the current page UI store. The extension reads those already-loaded fields for visible authors and does not make extra X requests. A fully loaded visible author hover card may still supplement ordinary relationship facts for that exact handle: `*-unfollow` means the viewer follows the account, `*-follow` means they do not, and `userFollowIndicator` means the account follows the viewer. Hover cards never contribute evidence to a different author.

When the active observer still has zero records, empty-state copy may mention hover as a fallback. That is not a claim that Home requires opening every hover card.

DOM mutations normally trigger an immediate debounced pass. While the consented observer page is visible, a 2-second fallback rescan covers reused nodes and missed asynchronous updates; returning focus or visibility triggers an immediate pass. Hidden pages pause periodic work, and signature deduplication prevents unchanged evidence from appending history every interval.

JSON export preserves users and observation history. CSV export contains the current user summary. Import accepts only a Not Brother JSON export and merges it into local data.

Unreviewed changes are specific when the stored transition is a single attributable action: a current mutual state displays mutual. One-way following displays following-only unless history shows they used to follow the viewer, in which case it displays unfollowed-you (mutual or follows-you-only to following-only). Mutual to follows-you-only displays you-unfollowed, and a known normal relationship to blocked-by displays blocked-you. Neither-following, including follows-you-only to none, removes the badge instead of showing a change label. Other double-action transitions remain generic. Page badges, recent records, and the fieldbook show the event; the dock keeps one aggregate changed count. Reviewing the change restores the current base-relationship label without deleting history.

In the Side Panel, activate a base-relationship count or the changed callout to filter the recent list; activate the selected category again to show all recent users. A filtered view shows up to 40 recent matches and an explicit empty state when none exist. Activating a user row opens that standard X profile in a new tab from the user gesture; it does not start automated traversal. In the fieldbook, the avatar, display name, and @handle share that same profile link. Avatars prefer the stored X CDN URL captured for that handle, then a public handle image (`https://unavatar.io/x/{handle}`) if none is stored.
