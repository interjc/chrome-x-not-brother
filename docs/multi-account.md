# 多账号：按登录账号分开档案

适用版本：0.6.0 起。

## 1. 问题

同一个 Chrome 里切换多个 X 账号时，出现了两个叠加的问题。

**账号切换菜单被当成资料浮窗。**

- 点左下角账号按钮，弹出的账号菜单和资料浮窗用同一个页面标记 `[data-testid="HoverCard"]`。
- 0.5.x 把它当成别人的资料浮窗处理，所以菜单里出现了「加入"不是兄弟"名单」按钮。
- 菜单里没有「正在关注 / 关注者」链接，正好触发了"已加载浮窗缺少关注数 = 拉黑了你"这条规则。
- 结果：无论用哪个账号打开菜单，顶部都出现「拉黑了你」，紧挨着自己那一行，看起来像自己拉黑了自己。原因见第 3 节。

**档案不分账号。**

- 0.5.x 的 users / observations 只按对方 handle 存，"当前账号"全局只记一个。
- 关系是相对的："@A 关注了 X"和"@B 关注了 X"是两件事，却写进了同一条记录。
- 换账号后，上一个账号的记录照样会被读出来，显示在页面和侧栏上。

只给数据加 scope 修不了第一个问题：误判来自页面识别，换到哪个账号的档案都会发生。两个都要修。

## 2. 改动概览

| 部分 | 做什么 |
| --- | --- |
| 识别账号菜单 | 账号菜单不再当资料浮窗：不采集、不打徽标、不放快捷加入按钮 |
| 记住自己的账号 | 每识别到一个登录账号就记下；任何档案里都不采集、不显示自己的账号 |
| 档案按账号分开 | 每条 users / observations 记录多一个 `viewer`（登录账号 handle，小写） |
| 自动升级旧数据 | 旧档案整份迁到新表，自动归到最后一次识别到的账号 |
| 切换时合并或清理 | 新账号没有档案时，侧栏提示可以从其他账号复制，或从空白开始；档案库可以合并、清空任一账号的档案 |
| 导出格式 v2 | 备份带上所属账号；v1 旧备份仍可导入 |

拦截规则和拦截计数早已按登录账号分开存，这次档案也统一到同一个命名空间。

## 3. 识别账号菜单

### 根因

0.5.x 把账号菜单当资料浮窗时，取到的"浮窗主人"是菜单底部「登出」链接 `/logout` 里的 `logout`，因为当时的路由保留字里没有它。于是扩展认为有一个叫 `@logout` 的账号：

- 菜单里没有它的「正在关注 / 关注者」链接，在帖子页上触发了浮窗 blocked-by 规则；
- 菜单本身没有用户名区域，徽标就挂在菜单最上方，紧挨着当前账号那一行；
- 每个账号打开菜单都一样，所以"两个账号都说自己被拉黑了"。

### 识别特征

X 网页版的结构没有官方文档。下面的特征先从公开的开源项目和脚本里查到，2026-11-05 又在真实页面上核对过（Chrome，两个账号，中文界面）。

| 特征 | 来源 |
| --- | --- |
| 菜单项 `data-testid` 为 `AccountSwitcher_AddAccount_Button`、`AccountSwitcher_ManageAccounts_Button`、`AccountSwitcher_Logout_Button` | X 自己的 SideNav 前端代码，以及 classic-twitter、Xtra 等扩展、多个 Selenium 脚本 |
| 菜单项链接为 `/i/flow/login`、`/account/switch`、`/logout` | 同上；OldTwitter 用 `/account/switch?newtwitter=true` |
| 菜单外层是 `[data-testid="HoverCard"]` | Control Panel for Twitter 的注释 "Account switcher accounts: `[data-testid="HoverCard"] button[data-testid="UserCell"]`" |
| 其他账号行是 `button[data-testid="UserCell"]` | 同上；一份 2026 年 8 月的 X 页面结构调研也是这么记录的 |

真实页面上，账号菜单这个 HoverCard 里只有下面这些：

| 类型 | 值 |
| --- | --- |
| 链接 | `/i/flow/login`、`/account/switch`、`/logout`，没有任何资料页链接 |
| `data-testid` | `UserCell`、`UserAvatar-Container-<当前账号>`、`icon-verified`、`UserAvatar-Container-<其他账号>`、`AccountSwitcher_AddAccount_Button`、`AccountSwitcher_ManageAccounts_Button`、`AccountSwitcher_Logout_Button` |

这也证实了根因：菜单里唯一能读成 handle 的链接就是 `/logout`。账号行里没有 `User-Name`，handle 只出现在文字里。

只要 HoverCard 里出现以下任一项，就把它当作账号菜单：

- `[data-testid^="AccountSwitcher_"]`
- 指向 `/logout`、`/account/switch`、`/i/flow/login` 的链接
- `button[data-testid="UserCell"]`：真正的资料浮窗里不会有 UserCell 按钮

每次页面变化都会重新判断，菜单项晚于账号行渲染也能识别。

### 处理

账号菜单整块跳过：

- 不作为资料浮窗参与关系判断，包括 blocked-by 浮窗规则；
- 菜单里的账号行不作为候选人，不打徽标；
- 不插入快捷加入按钮。

另外：

- `logout`、`login`、`signup`、`account`、`intent`、`share`、`hashtag`、`oauth` 加入路由保留字，任何地方都不会再把它们读成 handle；
- 升级时直接丢弃旧档案里 key 是这些保留字的记录，比如已经写进去的 `@logout`。

即使 X 以后改了菜单结构、上面的特征失效，下一节的"自己的账号"排除也会兜底。

## 4. 自己的账号

- 本机 `chrome.storage.local` 的本地设置里新增 `knownViewerHandles`：识别到过的登录账号列表，小写，最多 20 个。不进入 Chrome Sync。
- 内容脚本每次上报都会带上当前登录账号；service worker 发现新账号时：
  1. 加入 `knownViewerHandles`；
  2. 从所有账号的档案里删除这个账号的记录和历史。
- 写入、页面查询、侧栏、档案库、导出、合并都排除 `knownViewerHandles` 里的所有账号，和以前排除当前账号一样。
- 结果：@A 和 @B 之间的关注关系不再显示。这是有意的取舍，自己的小号不需要被标注。

## 5. 数据库：v1 → v3

数据库名不变（`not-brother-v1`），Dexie version 从 1 升到 3。

| version | 内容 |
| --- | --- |
| 1 | 旧表 `users`（主键 `key`）、`observations` |
| 2 | 新表 `accountUsers`（主键 `[viewer+key]`）、`accountObservations`（`[viewer+userKey]`、`[viewer+userKey+observedAt]` 索引）；把旧表整份复制过去，`viewer` 先填空字符串，表示"未归属" |
| 3 | 删除旧表 |

IndexedDB 升级事务里不能读扩展设置，所以复制时只能先标"未归属"，后续由 service worker 认领：

1. service worker 启动时，如果本地设置里已有 `viewerHandle`（最后一次识别到的登录账号），就把未归属记录全部归给它；
2. 如果还没有，就在第一次收到带登录账号的上报时归给那个账号；
3. 认领时按导入规则合并：以 `lastSeenAt` 较新的记录为准，保留最早首次时间、较大计数、任一侧的待确认变化；历史按 `userKey + observedAt` 去重；
4. 认领结果（账号、人数、时间）写进本地 `notBrother.legacyArchiveClaim.v1`，档案库用它显示一次性提示。

识别不到登录账号时（未登录、页面结构变化），本次观察直接丢弃，不再产生未归属数据。

## 6. 读写都带账号

| 入口 | 账号从哪来 |
| --- | --- |
| `observations:upsert` | 只认消息里的 `viewerHandle`，即这个页面自己显示的登录账号；缺省时丢弃，不用本地设置里的 `viewerHandle` |
| `users:lookup` | 消息新增 `viewerHandle` 字段；内容脚本只在页面显示了登录账号时查询 |
| `summary:get` | 消息里的 `viewerHandle`，缺省时用本地设置里的 `viewerHandle`（只影响 dock 概览数字） |
| 侧栏 | 本地设置里的 `viewerHandle`，即最后一次识别到的 X 账号 |
| 档案库 | 默认同侧栏，可以在顶部切换查看其他账号的档案 |

写入和查询不回退到本地设置里的账号：它是"最后一次识别到"的账号，刚切换完时就是上一个账号。页面暂时没画出左下角账号按钮（刚加载、窄窗口布局）时，这一轮的观察不写入、也不查档案，页面上只按现场证据打徽标。

切换账号时 X 会整页重新加载，内容脚本随之重新启动，缓存天然是空的。万一 X 以后改成不刷新页面直接切换，内容脚本在登录账号变化时也会清空本页的记录缓存、查询记录和上报去重签名，让新账号的档案重新查询、重新写入；切换前发出、切换后才返回的概览请求会被丢弃。

本地设置里的 `viewerHandle` 决定侧栏显示哪个账号，所以每次切换都必须更新它。观察器开着时，正常上报就会带上新账号；观察器暂停（例如只开了时间线过滤）时，内容脚本也会在同意后发一次不含观察的上报，只用来记下新账号，否则侧栏和规则页会停在上一个账号。账号一变，侧栏先清空列表再读新账号的档案，不会短暂显示上一个账号的记录。

## 7. 切换账号：合并或清理

### 侧栏提示

侧栏「状态」页标题下显示「@A 的档案」。当前账号还没有任何记录、而其他账号有记录时，显示提示：

> @B 还没有档案。@A 有 120 条记录。升级前的旧档案都归在 @A；如果以前也用 @B 浏览过，其中一部分其实是 @B 的。
>
> [复制 @A 的档案到这里] [从空白开始]

- 「复制」把那个账号的记录和历史复制到当前账号，源账号保留不动。
- 「从空白开始」只是关掉提示，记在本地 `dismissedArchivePrompts`，以后不再对这个账号提示。
- 有多个其他账号时，按记录数从多到少列出，每个一个复制按钮。

### 档案库的数据管理

档案库顶部多一行「档案所属账号」：

- 下拉切换查看任一账号的档案，标出当前登录的账号和每个账号的人数；
- 「合并到 @当前账号」：把正在查看的账号档案复制到当前账号，源账号保留；
- 原来的清空按钮只清空正在查看的这个账号；
- 自动认领旧数据后，显示一次性提示：「升级前的旧档案（N 人）已自动归到 @A。如果其中有其他账号的数据，可以在这里合并或清空。」

### 为什么不自动合并

关系是相对的，把 @A 的档案合并进 @B，等于假设 @B 和 @A 关注了同一批人。这个功能只用来收拾升级前混在一起的数据，所以：

- 从不自动合并，只在用户点按钮时执行；
- 按钮旁的说明写明这一点；
- 复制过来的记录会在 @B 之后的浏览中被新的页面证据覆盖，自然更正。

## 8. 导出与导入

导出 JSON 升到 `schemaVersion: 2`，新增顶层 `viewerHandle`（导出时所查看的账号）。users / observations 里不带 `viewer` 字段，结构和 v1 相同。

| 导入的文件 | 导入到哪里 |
| --- | --- |
| v1（0.5.x 及更早） | 档案库正在查看的账号 |
| v2，`viewerHandle` 与正在查看的账号相同 | 直接导入 |
| v2，`viewerHandle` 不同 | 先确认「这份备份来自 @X，要导入到 @Y 吗？」 |

导入后照样排除当前账号和所有自己的账号。CSV 导出不变。

## 9. 回滚

0.6.0 把数据库升到 version 3，0.5.x 打不开更高版本的数据库，档案库会读不出来。要退回 0.5.x：

1. 先在 0.6.0 的档案库里逐个账号导出 JSON；
2. 卸载扩展（会删除本地数据库），再安装 0.5.x；
3. 0.5.x 只认 schema v1 备份，不能直接导入 v2。需要的话，把文件里的 `"schemaVersion": 2` 改成 `1` 并删掉 `viewerHandle` 一行，再导入。

## 10. 验收清单

- [ ] 从 0.5.x 升级：旧档案人数不变，自动归到最后登录的账号，档案库显示一次性提示。
- [ ] 打开账号菜单：两个账号都没有「拉黑了你」，菜单里没有快捷加入按钮；档案里没有 `@logout`。
- [ ] 切换到另一个账号：侧栏显示新账号名，出现复制 / 从空白开始的提示；页面上不再显示上一个账号的徽标。
- [ ] 暂停观察器、只开时间线过滤后切换账号：侧栏和规则页跟着切到新账号。
- [ ] 点「复制」：当前账号出现同样的记录，源账号仍在。
- [ ] 点「从空白开始」：提示消失，刷新后不再出现。
- [ ] 档案库切换账号、合并、清空都只影响所选账号。
- [ ] 导出 v2 再导入：人数一致；导入 v1 旧备份正常。
- [ ] 自己的任一账号不出现在任何账号的档案、侧栏、页面徽标里。
